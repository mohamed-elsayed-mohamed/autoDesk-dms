# Plan prompt: 002 Customer Relationship Management (CRM)

**Use with:** `/speckit.plan` — paste the content below into the command.

**Spec:** [specs/002-crm/spec.md](../../specs/002-crm/spec.md)

---

Create the technical implementation plan for the **002-crm** feature. Follow the project constitution (`.specify/memory/constitution.md`) and this tech stack:

**Backend**
- Node.js with NestJS and TypeScript. New modules: `customers`, `leads`, `activities`, `tasks`. Reuse existing `auth` module and user/role infrastructure from 001-vehicle-inventory. Clean Architecture: controller → service → repository. Use Prisma as the ORM with PostgreSQL. REST API under `/api/customers`, `/api/leads`, `/api/activities`, `/api/tasks`. Customer search must support partial-match on name, phone, and email and return results within 1 second (up to 50k records). Duplicate detection: on create/edit, query by phone and email and return matching records as warnings (advisory, non-blocking). Lead assignment: manual to any active Sales Consultant, or round-robin auto-assignment rotating among active Sales Consultants. Lead reassignment: Sales Managers only (FR-009a). Round-robin state: track last-assigned index in-memory or DB. Lead status transitions: record a timestamp per transition; non-sequential (can move backward). "Lost" leads can be reopened (be-back); "Sold" leads cannot. Lost reason: optional free-text captured on transition to "Lost". Vehicles of interest: many-to-many between leads and vehicles (from 001-vehicle-inventory); retain read-only reference if vehicle is sold/removed. In-app notifications: notify assigned salesperson on new lead assignment or reassignment (FR-009b); simple DB-backed notification model (no WebSockets required for v1 — polling is acceptable). Customer soft-delete/archive: managers can archive and restore customers; archived customers hidden from active lists but all linked data preserved. All list endpoints must support pagination (default page size 25), sorting, and filtering. Activities are immutable once created (no edit/delete). Tasks: Pending → Completed | Cancelled; overdue = past due_at and still Pending.

**Frontend**
- React with TypeScript. Reuse existing component library (Material UI or Ant Design), layout shell, auth/routing from 001. New pages/views: Customer list (search, filter, paginate); Customer create/edit form (with inline duplicate warning); Customer profile/detail (contact info, linked leads list, combined activity timeline); Lead list (filter by status, assignee, source, date range; paginate); Lead create form (with inline customer creation option, source picker, salesperson assignment, vehicle-of-interest multi-select from inventory); Lead detail (pipeline status widget, vehicle(s) of interest, activities, tasks); Pipeline board or status view for Sales Managers; Activity log form (type, direction, content — accessible from lead and customer views); Activity timeline component (reverse-chronological, paginated, labeled by lead); Task create form (due date/time, description, linked to lead); "My Tasks for Today" view (today + overdue, overdue visually flagged); Manager task oversight view (filter by salesperson). Notification indicator (badge/bell) showing unread lead assignment notifications. Empty, loading, and error states on all views. Shared TypeScript types for Customer, Lead, Activity, Task, Notification.

**Auth & Roles**
- Leverage existing JWT auth from 001. Roles relevant to CRM: Sales Consultant, BDC Agent, Sales Manager. Sales Consultants and BDC Agents: full CRUD on customers, leads, activities, tasks they own. Sales Managers: all of the above plus lead reassignment, customer archive/restore, team-wide task and lead visibility. Enforce at API level with guards/decorators.

**Database**
- PostgreSQL via Prisma. New models: Customer (firstName, lastName, email, phone, street, city, state, zip, preferredContact, notes, archivedAt, createdAt, updatedAt), Lead (customerId, source, sourceOther, status, assignedTo, lostReason, notes, createdAt, updatedAt), LeadVehicle (leadId, vehicleId — join table for many-to-many), LeadStatusHistory (leadId, fromStatus, toStatus, changedBy, changedAt), Activity (leadId nullable, customerId, type, direction nullable, content, performedBy, performedAt), Task (leadId, assignedTo, type, description, dueAt, completedAt, status, createdAt), Notification (userId, type, referenceId, message, readAt, createdAt). Indexes: customers(lastName, firstName), customers(email), customers(phone), leads(status), leads(assignedTo), leads(source), leads(createdAt), activities(customerId, performedAt), activities(leadId), tasks(assignedTo, status, dueAt). Soft-delete on Customer via archivedAt (null = active). Use migrations.

**Quality**
- Unit tests for: round-robin assignment logic, duplicate detection matching, lead status transition validation (block reopening Sold), overdue task calculation. Integration tests for: customer CRUD + search + duplicate warning, lead CRUD + pipeline transitions + reassignment, activity logging + timeline aggregation, task CRUD + "my tasks today" query, notification creation on assignment. E2E (Cypress): create customer with duplicate warning flow, create lead and move through pipeline, log activity and verify timeline, create task and verify overdue flagging, manager reassigns lead and salesperson sees notification. Follow constitution: test-first for business logic, API-first (implement and test API before UI).

**Out of scope for this plan**
- Deals, F&I, service, parts, accounting, OEM integration, AI lead scoring, email/SMS sending. No real-time WebSockets (polling for notifications is acceptable for v1). No data import/export. No territory-based or weighted lead routing.

Produce the implementation plan (plan.md), research.md if needed for notification patterns or round-robin strategies, data-model.md with the Prisma schema additions, and API contracts for all CRM endpoints. Align with the spec's user stories (P1 customer profiles, P2 lead capture/pipeline, P3 activities/timeline, P4 follow-up tasks) and clarifications (lead reassignment by managers, multiple vehicles per lead, be-back reopening, soft-delete customers, in-app assignment notifications).
